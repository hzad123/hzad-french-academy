# Owner-only exam audio preparation

The owner authorized publishing the exams and supplied their existing verified academy account for the audio setup tool. Deployment pins the **immutable Auth UUID**, outside public source, in `academy_exams.audio_operators`. The email and UUID are not embedded in the browser, public migration or provider prompt. No login, email verification, purchase entitlement or student wallet is bypassed or modified.

After signing into that account on the academy, choose **TEF/TCF AI Tests** at the top right, then **Audio setup** and **Generate exam audio**. The browser processes one original recording per request and shows saved progress. Keep the tab open to continue the set; Stop finishes the in-flight recording before pausing. Reopening/refreshing retrieves existing progress. Only the fixed 79 versioned scripts can be generated. The setup uses the existing server-side `OPENAI_API_KEYfrench` and `gpt-4o-mini-tts`; no new key needs to be copied into the cloud environment or browser. The generation estimate is CAD $2–$5 for the set, not a provider invoice or student charge.

Each request independently verifies the actual Supabase user and its database capability. The gateway retains JWT verification. `20261105001400_exam_audio_admin.sql` contains empty operator grants and the fixed 79 script hashes. The only browser request parameters are action/path/audio hash/review confirmation, never an arbitrary provider model, prompt, key, destination or owner identity. Operators cannot self-grant through the public API, and ordinary students receive 403. The provider is called only after an atomic single-use claim. A global claim lock prevents multiple workers claiming different assets concurrently, including if a second operator is granted later. Completed files cannot be overwritten. Failed/uncertain calls never automatically repeat a paid request; an interrupted status requires inspection before any manually authorized reset.

Recordings are uploaded to the existing **private** listening bucket, without upsert. Audio hashes/byte lengths and review provenance are retained. Listen to each ready asset, check its full French script/question, pacing, pronunciation and volume, then confirm and choose Approve recording. The UI waits for playback to end before enabling approval; the server checks a prior preview and the current immutable audio hash. This is human sign-off, not a claim of automatic linguistic quality verification. Full audio approval marks only `audio_reviewed`; it does not enable the exam, set prices, edit student credits or override separate editorial/model-cost release checks.

This is an explicit owner-triggered setup task: no cron, background billing loop, public generation endpoint or maintenance deletion job is installed. `supabase/rollbacks/20261105_disable_exam_audio_admin.sql` revokes execution without removing generated files or modifying learning data. If a paid call fails or a worker disappears after uploading a file, inspect the object and saved claim before reconciliation; do not blindly reset or rerun the generation script.

Validation includes local PostgreSQL tests for capability isolation, verification, restricted grants, manifest/hash integrity, concurrent/repeated claims, retained failures and review gating; handler/provider tests cover fixed paid inputs, output bounds and unauthorized denial. Desktop/mobile browser checks exercise visibility, progress/resume, stop/review and sign-out cleanup with test doubles. Live paid generation remains unverified until the owner signs in and starts it. No recording is automatically marked reviewed.

All 139 Node tests and the standard build passed before rollout. Desktop 1440px/mobile 390px fixture checks passed for restricted visibility, generation/resume, one call per file, full-playback approval, sign-out cleanup and no horizontal overflow/JavaScript errors.
